# v4.1 — Construtor de Dashboards + ECharts

> **Status:** Ticket pronto para execução
> **Release:** v4.1 (segunda de 4)
> **Pré-requisito:** v4.0 (datasets livres + import/export) ✅
> **Objetivo:** Permitir que cada projeto tenha múltiplos dashboards customizáveis, com gráficos via ECharts, slicers/filtros, e widgets (KPI, tabela, pivot). Primeiro dashboard criado automaticamente tem widgets "Tabela — Locais" e "Tabela — Itens" (compatibilidade).

---

## 1. Resumo

Esta release entrega o **construtor visual de dashboards** sobre os datasets livres (v4.0). O usuário cria dashboards por projeto, adiciona widgets vinculados a datasets, configura agregações (sum, avg, count, min, max) por campos, e usa slicers para filtrar múltiplos widgets de uma vez.

Duas lanes paralelas: **backend (foundation + agregador + routers + tests)** e **frontend (DashboardBuilderPage + ECharts + widgets + slicers + smoke)**.

## 4. Modelo de dados

### `dashboards`

```sql
CREATE TABLE IF NOT EXISTS public.dashboards (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    projeto_id BIGINT NOT NULL REFERENCES public.projetos(id) ON DELETE CASCADE,
    nome TEXT NOT NULL,
    layout_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    eh_interno BOOLEAN NOT NULL DEFAULT FALSE,
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    atualizado_em TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_dashboards_projeto ON public.dashboards(projeto_id);
CREATE INDEX IF NOT EXISTS idx_dashboards_interno ON public.dashboards(eh_interno) WHERE eh_interno = TRUE;
```

### `widgets`

```sql
CREATE TABLE IF NOT EXISTS public.widgets (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    dashboard_id BIGINT NOT NULL REFERENCES public.dashboards(id) ON DELETE CASCADE,
    type TEXT NOT NULL,  -- "bar"|"line"|"pie"|"area"|"scatter"|"kpi"|"table"|"pivot"
    dataset_id TEXT NOT NULL,  -- aceita int (str) OU "locais-{pid}"/"itens-{pid}"
    config_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    position_json JSONB NOT NULL DEFAULT '{"x":0,"y":0,"w":4,"h":3}'::jsonb,
    ordem INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_widgets_dashboard ON public.widgets(dashboard_id, ordem);
```

### `slicers`

```sql
CREATE TABLE IF NOT EXISTS public.slicers (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    dashboard_id BIGINT NOT NULL REFERENCES public.dashboards(id) ON DELETE CASCADE,
    dataset_id TEXT NOT NULL,
    field TEXT NOT NULL,
    values_json JSONB NOT NULL DEFAULT '[]'::jsonb,
    tipo TEXT NOT NULL  -- "lista"|"intervalo"|"data"
);
CREATE INDEX IF NOT EXISTS idx_slicers_dashboard ON public.slicers(dashboard_id);
```

**Espelho SQLite** em `backend/history.py` (mesmas 3 tabelas com tipos SQLite, JSON como TEXT).

## 5. Tipos de widget (v4.1)

| type | Descrição | Configuração |
|---|---|---|
| `bar` | Gráfico de barras ECharts | `{x: string, y: string[], aggregation: "sum"\|"avg"\|"count"\|"min"\|"max"}` |
| `line` | Gráfico de linha ECharts | mesma config |
| `pie` | Gráfico de pizza ECharts | mesma config |
| `area` | Gráfico de área ECharts | mesma config |
| `scatter` | Dispersão ECharts | `{x, y}` |
| `kpi` | Número único + variação | `{field: string, aggregation, comparacao?: "anterior"\|"media"}` |
| `table` | Tabela simples | `{colunas: string[]}` |
| `pivot` | Pivot table (custom, não ECharts) | `{linhas: string[], colunas: string[], metrica: string, aggregation}` |

Demais tipos (heatmap, funnel, stacked, combo) viram em v4.2 ou v4.3. Mantenha v4.1 focado no essencial.

## 6. Endpoints (todos exigem login)

```
GET    /api/projetos/{id}/dashboards                 lista dashboards do projeto (limite 20)
POST   /api/projetos/{id}/dashboards                 cria dashboard. Se for o 1º, popula com widgets locais/itens. Body: {nome, layout_json?, eh_interno?}
GET    /api/projetos/{id}/dashboards/{dbid}          obtém dashboard completo (com widgets + slicers)
PATCH  /api/projetos/{id}/dashboards/{dbid}          atualiza nome/layout/eh_interno
DELETE /api/projetos/{id}/dashboards/{dbid}          remove (cascata widgets + slicers)

POST   /api/dashboards/{dbid}/widgets                adiciona widget. Body: {type, dataset_id, config_json, position_json}. Limite 50 widgets/dashboard
PATCH  /api/dashboards/{dbid}/widgets/{wid}          atualiza widget
DELETE /api/dashboards/{dbid}/widgets/{wid}          remove widget

POST   /api/dashboards/{dbid}/slicers                adiciona slicer. Body: {dataset_id, field, tipo}
DELETE /api/dashboards/{dbid}/slicers/{sid}          remove slicer

POST   /api/dashboards/{dbid}/query                  executa query agregada. Body: {widget_ids?: string[], slicer_ids?: string[]}. Retorna: {widgets: [{widget_id, data: {...}, type}], slicers: [{slicer_id, options: [...]}]}
```

## 7. Estratégia de agregação (dual)

**Padrão:** SQL com `GROUP BY` no banco Neon para volumes > 1000 linhas; Python puro para volumes menores ou campos calculados.

```python
# backend/agregador.py
def agregar(dataset_id: str, group_by: list[str], aggregation: str,
            filters: dict = None, slicers: list[dict] = None) -> dict:
    """Retorna {groups: [{key: {...}, value: N}, ...], total: N}"""
```

- Se `dataset_id` é virtual (`locais-{pid}` ou `itens-{pid}`), consulta SQL direto em `locais`/`itens` com JOIN apropriado.
- Se `dataset_id` é numérico, consulta `dataset_rows.data_json` (Postgres `jsonb` com `->>` para extrair campos) + `GROUP BY`.
- Filtros aplicados como `WHERE`.
- Slicers aplicados como `WHERE ... IN (...)` ou `WHERE ... BETWEEN ... AND ...`.

**Performance:** alvo < 2s para 100k linhas. Use EXPLAIN para verificar plano. Se necessário, criar índices em `dataset_rows (dataset_id)` (já existe).

## 8. Frontend — Estrutura de páginas

### `DashboardBuilderPage.tsx`

- Sidebar esquerda: lista de dashboards do projeto. Botão "+ Novo dashboard".
- Área central: modo **edição** ou **visualização**:
  - **Edição:** grid com drag-and-drop (pode usar `react-grid-layout`, mas evita nova dep — use drag nativo via state). Painel direito com config do widget selecionado.
  - **Visualização:** widgets renderizados em grid simples; slicers no topo.
- Toolbar superior: alternar edição/visualização, slicer bar, botão "Compartilhar" (placeholder — funcional em v4.3).

### `widgets/BarChart.tsx`, `LineChart.tsx`, `PieChart.tsx`, etc.

Wrapper de ECharts via `echarts-for-react`. Recebe `data` (output do agregador) + `config` (do widget). Tema `dark` para casar com projeto.

### `widgets/KpiCard.tsx`

Card com número grande + label + variação (% vs anterior ou média).

### `widgets/TableWidget.tsx`

Tabela HTML simples com `colunas` da config e `data` do agregador.

### `widgets/PivotWidget.tsx`

Pivot table custom (sem AG Grid Enterprise). Agrega client-side a partir de `data` (output do backend já agrupado por `linhas × colunas × metrica`).

### `SlicerBar.tsx`

Renderiza os slicers do dashboard. Tipos:
- `lista` — multi-select dropdown
- `intervalo` — min/max number inputs
- `data` — date range picker
