> **Status:** Ticket pronto para execução

## 1. Resumo

Esta release entrega os recursos finais da v4: compartilhamento público de dashboards (link com token), agendamento automático de relatórios em PDF, armazenamento em R2, e auditoria básica.

Lanes paralelas: **backend (publicações/agendamentos/relatórios/audit/R2/rate limit)** e **frontend (páginas Compartilhados/Relatórios + PublicoPage)**.

## 4. Modelo de dados

### `publicacoes`

```sql
CREATE TABLE IF NOT EXISTS public.publicacoes (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    dashboard_id BIGINT NOT NULL REFERENCES public.dashboards(id) ON DELETE CASCADE,
    token TEXT NOT NULL UNIQUE,
    revogado_em TIMESTAMPTZ,
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    criado_por BIGINT NOT NULL REFERENCES public.usuarios(id)
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_publicacoes_token ON public.publicacoes(token);
```

### `agendamentos`

```sql
CREATE TABLE IF NOT EXISTS public.agendamentos (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    publicacao_id BIGINT NOT NULL REFERENCES public.publicacoes(id) ON DELETE CASCADE,
    periodicidade TEXT NOT NULL,  -- "diaria"|"semanal"|"mensal"|"on_demand"
    proxima_execucao TIMESTAMPTZ NOT NULL,
    ativo BOOLEAN NOT NULL DEFAULT TRUE,
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    criado_por BIGINT NOT NULL REFERENCES public.usuarios(id)
);
CREATE INDEX IF NOT EXISTS idx_agendamentos_proxima ON public.agendamentos(proxima_execucao) WHERE ativo = TRUE;
```

### `relatorios`

```sql
CREATE TABLE IF NOT EXISTS public.relatorios (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    agendamento_id BIGINT REFERENCES public.agendamentos(id) ON DELETE SET NULL,
    publicacao_id BIGINT NOT NULL REFERENCES public.publicacoes(id) ON DELETE CASCADE,
    gerado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    storage_key TEXT NOT NULL,  -- caminho no R2 (ex.: "relatorios/dashboard-42/2026-08-19.pdf")
    tamanho_bytes BIGINT,
    status TEXT NOT NULL DEFAULT 'gerado'  -- "gerado"|"falha"
);
CREATE INDEX IF NOT EXISTS idx_relatorios_publicacao ON public.relatorios(publicacao_id, gerado_em DESC);
```

### `audit_log`

```sql
CREATE TABLE IF NOT EXISTS public.audit_log (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    evento TEXT NOT NULL,  -- "publicacao"|"revogacao"|"download_relatorio"
    usuario_id BIGINT REFERENCES public.usuarios(id),
    alvo_id BIGINT,
    alvo_tipo TEXT,
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    metadata_json JSONB DEFAULT '{}'::jsonb
);
CREATE INDEX IF NOT EXISTS idx_audit_log_evento ON public.audit_log(evento, criado_em DESC);
```

**Espelho SQLite** em `backend/history.py` (4 tabelas com tipos SQLite, JSON como TEXT).

## 5. Endpoints (todos exigem login, exceto `/p/{token}`)

```
# Publicações
POST   /api/dashboards/{dbid}/publicar              body: {} → {token, url_publica: "/p/{token}"}
DELETE /api/publicacoes/{pid}                       revoga (revogado_em = NOW())

# Compartilhados (internos)
GET    /api/dashboards/compartilhados               lista dashboards com eh_interno=true (sem prefixo de projeto)

# Agendamentos
POST   /api/agendamentos                            body: {publicacao_id, periodicidade}
GET    /api/agendamentos                            lista
PATCH  /api/agendamentos/{aid}                      atualiza (ativo, periodicidade)
DELETE /api/agendamentos/{aid}                      remove

# Relatórios
GET    /api/relatorios                              lista
GET    /api/relatorios/{rid}/download               baixa PDF (proxy do R2, registra audit_log)

# Auditoria (admin)
GET    /api/audit-log                               lista eventos (com filtros)

# Cron (autenticado por header)
POST   /api/cron/relatorios                         processa agendamentos pendentes (gera PDFs + envia R2)

# Público (NÃO exige login, com rate limit 60 req/min/IP)
GET    /p/{token}                                   renderiza dashboard publicado (read-only)
```

## 9. Rate limit (`backend/main.py`)

Usar `slowapi`:

```python
from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter

# Em routers/publico.py:
@app.get("/p/{token}")
@limiter.limit("60/minute")
def render_publico(request: Request, token: str):
    ...
```

**Storage do rate limit:** em memória por padrão. Se a Vercel tiver múltiplas instâncias serverless, o rate limit pode não ser compartilhado — mas para v4.3 o limite por instância é aceitável (60 req/min por IP). Se necessário, mover para Upstash Redis depois.

## 16. Notas para implementação

### Backend

- Reutilize padrão de `datasets_store.py` para `publicacoes_store.py`, `agendamentos_store.py`, etc.
- Para o rate limit, se `slowapi` em memória for insuficiente, considere `slowapi[redis]` + Upstash (mas só se houver evidência de problema).
- O endpoint público `/p/{token}` NÃO tem `Depends(usuario_atual)` — é o único endpoint sem auth.
- Use `secrets.token_urlsafe(32)` para gerar tokens.
- PDFs no R2 ficam sob `relatorios/dashboard-{id}/{YYYY-MM-DD}-{timestamp}.pdf`.

### Frontend

- `PublicoPage` é a única página **fora** do layout `AppShell` (não tem menu lateral).
- Use o mesmo wrapper de widgets (`components/widgets/`) mas em modo read-only.
- Para a aba Relatórios, adicione link no menu superior (`AppShell` ou equivalente).

### Infra

- Crie a conta Cloudflare (se ainda não existe) antes de subir para produção. Bucket + access keys.
- Adicione as 4 env vars do R2 + `CRON_SECRET` na Vercel.
- Teste o cron manualmente: `curl -X POST -H "Authorization: Bearer $CRON_SECRET" https://.../api/cron/relatorios`.
