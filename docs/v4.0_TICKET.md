## 4. Modelo de dados

### `datasets` (aditiva)

```sql
CREATE TABLE IF NOT EXISTS public.datasets (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    projeto_id BIGINT NOT NULL REFERENCES public.projetos(id) ON DELETE CASCADE,
    nome TEXT NOT NULL,
    schema_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    fonte TEXT NOT NULL DEFAULT 'livre',  -- "livre" apenas nesta fase; "locais"/"itens" virá como virtual
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    atualizado_em TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_datasets_projeto ON public.datasets(projeto_id);
```

### `dataset_rows` (aditiva)

```sql
CREATE TABLE IF NOT EXISTS public.dataset_rows (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    dataset_id BIGINT NOT NULL REFERENCES public.datasets(id) ON DELETE CASCADE,
    row_index INTEGER NOT NULL,
    data_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(dataset_id, row_index)
);
CREATE INDEX IF NOT EXISTS idx_dataset_rows_dataset ON public.dataset_rows(dataset_id, row_index);
```

**Nota:** o schema SQLite (`history.py`) deve espelhar estas tabelas com tipos equivalentes (TEXT/INTEGER em vez de JSONB/TIMESTAMPTZ, com `data_json`/`schema_json` como TEXT contendo JSON serializado).

### Datasets virtuais (locais/itens)

Conforme decisão da spec (REQ-012 / P3 — **Opção A: IDs especiais**), `locais` e `itens` **não ganham registros** na tabela `datasets`. Em vez disso:

- Widgets gravam `dataset_id` como **string** no formato `"locais-{projeto_id}"` ou `"itens-{projeto_id}"` quando o usuário seleciona uma fonte virtual.
- O agregador detecta o prefixo e consulta `locais`/`itens` diretamente.

**Nesta PR (Phase 1)**: o `datasets_store` deve retornar, no `listar_datasets()`, as duas entradas virtuais (`locais-{projeto_id}` e `itens-{projeto_id}`) com `fonte = "locais"`/`"itens"` e `schema_json` derivado das colunas reais das tabelas. Os endpoints GET devem aceitar o ID virtual e resolver para os dados de `locais`/`itens`. CRUD normal (POST/PATCH/DELETE) só funciona com IDs numéricos; IDs virtuais retornam 405/400.

## 5. Endpoints (todos exigem login)

| Método | Rota | Função |
|---|---|---|
| `GET` | `/api/projetos/{id}/datasets` | Lista datasets do projeto (inclui virtuais) |
| `POST` | `/api/projetos/{id}/datasets` | Cria dataset livre. Body: `{nome, schema_json}`. Limite **20 datasets/projeto** |
| `GET` | `/api/projetos/{id}/datasets/{did}` | Obtém dataset + schema. `did` pode ser `int` ou `locais-{pid}`/`itens-{pid}` |
| `PATCH` | `/api/projetos/{id}/datasets/{did}` | Atualiza `nome`/`schema_json`. Não funciona em IDs virtuais |
| `DELETE` | `/api/projetos/{id}/datasets/{did}` | Remove dataset (cascata em `dataset_rows`). Não funciona em IDs virtuais |
| `GET` | `/api/datasets/{did}/rows` | Lista linhas do dataset. Suporta virtual |
| `POST` | `/api/datasets/{did}/rows` | Adiciona linhas (bulk). Body: `{rows: [{row_index, data_json}, ...]}`. Não funciona em IDs virtuais. Limite **100k linhas/dataset** |

**Erros padrão:** `400` (validação/limite atingido), `401` (sem sessão), `404` (não encontrado), `405` (operação não permitida em ID virtual).

## 6. Padrões a seguir (do projeto)

- **Branching em `database_url()`** — `projetos_store.py` ramifica entre `psycopg` (Neon) e `sqlite3` (local). O novo `datasets_store.py` deve seguir o mesmo padrão.
- **Funções CRUD** retornam tuplas/dicts simples; serialização é feita no router.
- **Login obrigatório** — dependência `usuario_atual` em todos os endpoints (mesma usada em `routers/projetos.py`).
- **Schema aditivo no boot** — adicionar os `CREATE TABLE IF NOT EXISTS` em `schema.sql` e no `history.py` para SQLite, **executados na inicialização** (não em migration one-off).
- **Testes pytest** — seguir padrão de `backend/tests/test_projetos.py` (se existir) ou `backend/tests/`. Configurar `DATABASE_URL=""` antes de rodar para usar SQLite local.

## 9. Riscos e mitigações

| Risco | Mitigação |
|---|---|
| Schema aditivo no boot pode conflitar com schema existente | Usar `CREATE TABLE IF NOT EXISTS`; rodar `IF NOT EXISTS` em todos os índices também |
| Função `database_url()` ramificada precisa ser respeitada | Seguir exatamente o padrão de `projetos_store.py` (psycopg vs sqlite3) |
| IDs virtuais podem colidir com IDs numéricos | Usar prefixo não-numérico (`locais-`, `itens-`) — IDs numéricos nunca começam com letra |
| Limite de 20 datasets/projeto não existe no schema | Aplicar via contagem antes do INSERT no store; retornar 400 |
